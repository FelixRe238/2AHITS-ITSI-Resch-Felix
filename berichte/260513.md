#### Übung (Binary File Patching I)
Die Änderungen lassen sich auch permanent im Binärfile des Programms durchführen. Dazu analysiert man mit objdump -d pwcheck die Programmdatei um herauszufinden auf welchem Offset sich die zu manipulierenden Daten befinden.
```sh
~/workspace$ objdump -d pwcheck

pwcheck:     file format elf64-x86-64


Disassembly of section .init:

0000000000001000 <_init>:
    1000:   f3 0f 1e fa             endbr64
    1004:   48 83 ec 08             sub    $0x8,%rsp
    1008:   48 8b 05 e1 2f 00 00    mov    0x2fe1(%rip),%rax        # 3ff0 <__gmon_start__@Base>
    100f:   48 85 c0                test   %rax,%rax
    1012:   74 02                   je     1016 <_init+0x16>
    1014:   ff d0                   call   *%rax
    1016:   48 83 c4 08             add    $0x8,%rsp
    101a:   c3                      ret
...............
```
Bei der zeile 11c8 muss man den Code verändern, aus dem je (jump if equal) in 6 nop's (Befehle die nichts machen) dabei werden alle 6 Bytes überschrieben um das umzusetzen wird der Hexeditor verwendet
```sh
hexedit pwcheck
```
Mit CTRL + G zur position springen und dort den Befehl verändern auf 
90 90 90 90 90 90
Nach der Änderung CTRL + X und mit y speichern:
```sh
~/workspace$ ./pwcheck
Enter password: huas
Correct
Password was: G7pL9xQ2mR4tZcH
a=
```
Auch wenn das falsche Passwort eingegeben wird gibt das Programm Correct aus und es geht weiter.

#### Übung (Binary File Patching II)
Patche auch die Änderung von Addition auf Subtraktion ins Programm-Binary.

Der Add Befehl der gesucht wird befindet sich in der Zeile 1249:
```sh
1249:   03 44 24 08             add    0x8(%rsp),%eax
```
Das erkennt man daran dass kurz vor diesem Befehl zwei funktionen namens "....scanf...." hier erkennt man das einmal a und einmal b eingelesen werden.

Das wieder mit hexedit ändern:
03 -> 2b
(2b ist der Befehl für SUB)
```sh
~/workspace$ ./pwcheck
Enter password: schorscht
Correct
Password was: G7pL9xQ2mR4tZcH
a=30
b=15
Result=15
```
#### Übung (jne)
